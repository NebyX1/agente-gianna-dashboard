# Tickets IDL, contrato instalado 1.0

Usar catálogos vivos y usuario verificado. Registrar la descripción dictada fielmente.
Preguntar un dato faltante por turno. No inventar áreas, tipos, fechas ni prioridades.
La revisión identifica origen, destino, tipo y descripción. «Sí, es todo» confirma sólo
la revisión vigente. Las correcciones, cambios de usuario y expiraciones la invalidan.
Toda escritura usa la API delegada y una identidad durable. El navegador prepara una
vista previa que nunca envía el formulario. Un timeout obliga a consultar el recibo;
no autoriza otro ticket ni envío por UI. Sólo un recibo persistido autoriza anunciar éxito.
